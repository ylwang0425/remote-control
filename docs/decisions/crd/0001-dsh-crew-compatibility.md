# CRD 0001 — DSH / dsh-crew 兼容性修复提案

- **编号**: 0001
- **标题**: DSH 0.1.7-rc.1 + dsh-crew 0.9 的 PM write guard 兼容性修复与 Crew preset 声明式注册修复
- **日期**: 2026-10-08
- **状态**: **未执行兼容修复、未修改 DSH 安装文件、未部署应用**（待决定是否执行第 3、4 节）
- **申请人**: **Codex 协调者提出的前置兼容性修复**（不是用户要求修 guard）
- **撰写**: PM
- **关联文档**: `docs/design/prd-ai-remote.md`（PRD v2）、`docs/tasks/T-0001-dsh-compatibility.md`（前置任务与验证）
- **决策要求**: 本 CRD 的两项都会**改变实际可写权限边界**（真实子代理从"被拒"变为"可写"；PM 的 PTC 嵌套写从"被放行"变为"被拦"）。因此**需要用户本人明确接受后才可执行**，且**执行不等于可以绕过守卫**。
- **本提案不含**: 任何 shell 绕过、任何禁用守卫的方案、任何伪造 session header 的做法、任何产品代码新增路径。

## 0. 一页摘要（先读这段）

现场是 **DSH 0.1.7-rc.1** 配 **dsh-crew 0.9**。目前有两处不兼容，都会直接挡住本次"AI 远程控制"作业的开发：

1. **PM write guard 认错人**：它用"有没有 `parent` 字段"来判定"这是不是子代理"。在新 DSH 核心中，`parent` 只表示 **PTC transport 的嵌套派发**，与 subagent 谱系无关。结果：**真实子代理写代码被误拦**，而**PM 自己发起的 PTC 嵌套写反而可能被放行**。两边都要做回归验证。
2. **Crew preset 注册不上**：`preset_flash='crew'` 之后 spawn 返回 `Unknown agent preset: crew`。旧插件用 YAML 目录注册，而新版 registry 是**声明式注册**。

本 CRD 给出**最小、正常、可回滚**的修复提案，并**明确列出不允许的做法**。**在用户对第 3 节与第 4 节作出决定之前，不执行其中任何一步。**

## 1. 问题一：PM write guard 判定依据错误

### 1.1 现象（已实测）

| # | 现象 | 现场证据 |
| --- | --- | --- |
| 1 | 外部 MCP worker `hub-3-muyz3072` 用 `write` 写 `desktop` 代码，被 PM guard 拒绝；自动 approval 结果为 **rejected**；该 worker 已取消 | 本次会话现场记录 |
| 2 | **真实 subagent** 同样被拒：父 `hub-7-muyzd77j`，会话 `session-43eba504-6a72-48f6-a87a-1f334c521bd8`，子 `70cc6627-dfeb-4e4f-9535-5474d5c5cb4e`，用 `write` 被拒绝 | 本次会话现场记录 |
| 3 | 验证文件 `worker-proof.txt` **不存在**（因为写入被拒，从未产生） | 本次会话现场记录 |

结论：**这不是"子代理不该写"，而是"守卫认错了谁在写"。**

### 1.2 根因（两边证据）

**旧守卫侧（判定逻辑）**

- 文件：`C:\Users\Hi\.dsh\profiles\desktop\node_modules\dsh-crew\host\pm-write-guard.js`
- 行号：**273–294**
- 逻辑：仅凭 `exec.parent !== undefined` 断定"这是一次子代理写操作"，据此决定拦住还是放行。

**新 DSH 核心侧（`parent` 的真实语义）**

- 文件：`C:\Users\Hi\AppData\Roaming\npm\node_modules\@deepseek-ai\dsh\node_modules\@deepseek-ai\dsh-tools\lib\types\index.d.ts`
- 行号：**216–244**
- 结论：`ToolExecutionInput.parent` **只表示 PTC transport nested dispatch（PTC 传输的嵌套派发）**，**不是** subagent 谱系信息。

**真实子代理的定义在别处**

- 文件：`C:\Users\Hi\AppData\Roaming\npm\node_modules\@deepseek-ai\dsh\node_modules\@deepseek-ai\dsh-subagent\lib\types\child-agent.js`
- 行号：**108–125**
- 结论：`childSessionMeta` 记录**不可变 header**：
  `{ parentSession: parentHeader.id, origin: 'subagent', delegationDepth: childDepth }`

### 1.3 缺陷的两个方向（这是本 CRD 必须同时覆盖的原因）

| 方向 | 现状 | 后果 | 严重度 |
| --- | --- | --- | --- |
| **误拦（false negative for worker）** | 真实子代理写自己的任务领地 → 被拒 | 开发任务根本无法开工；且"被拒"看起来像是 agent 不听话，掩盖真实原因 | 阻塞（已实测） |
| **误放（false positive for PM）** | PM 自己发起的 **PTC 嵌套** `write` → `parent` 存在 → 被当作"子代理"→ **可能放行** | PM 直写保护路径被绕过，等于守卫在最该管的地方失效 | **安全**（同源推断，须同轮回归） |

> 方向二目前是**基于同一段代码的推断**，尚未像方向一那样被现场实测。因此第 3.5 节把它列为**必须成对验证**的回归项，而不是既成事实。

### 1.4 提案修复原则（建议方案，不锁实现细节）

**核心规则**：guard 判定"合法子代理"时，必须依据**运行时的权威 subagent lineage / 不可变 session header 来源**，**不得**把 `exec.parent` 是否存在当作宽松豁免条件。

配套原则（全部为约束，不是建议选项）：

1. **PM 原有白名单/审批模式保留**：修复只纠正"认错人"，不改变 PM 直写的保护意图。
2. **不增加产品代码路径**：这是守卫的判定修正，不是新功能。
3. **不禁用 guard**：任何形式的临时关闭、旁路开关、环境变量跳过都不接受。
4. **不赋予 root worker 子代理身份**：不得为了让某个 worker 通过而把它伪装成 subagent。
5. **不伪造 header**：不得手工构造 `origin: 'subagent'` 之类的 header 骗过判定。
6. **新旧 API 兼容适配必须用"明确版本 + 证据"**：需要兼容多个 DSH 版本时，用可核实的版本判定/能力探测，**绝不允许"只要存在 parent 就放行"**。

### 1.5 最小改动范围与"不改什么"

| 项 | 内容 |
| --- | --- |
| **改哪些文件（最小）** | 仅守卫判定相关文件（当前指向 `dsh-crew/host/pm-write-guard.js` 的判定段落）。若需同时修 preset 注册，则是 crew 插件注册相关文件（见第 4 节）。 |
| **不动哪些** | 不改其它角色定义、不改任何其它会话的 default、不改 `flash-only`、不动 `git-guard`、不动任何产品代码、不动服务器、不动 profile 的其它部分。 |
| **备份要求** | 修改前对**要改的每一个文件**做同目录时间戳备份（例如 `<file>.bak-<YYYYMMDD-HHmmss>`），备份路径写进执行报告。 |
| **durable patch 记录** | 任何对 `node_modules` 内文件的改动都是**临时补丁**，必须记录 **durablepatch 路径**（补丁文件或可重放的 patch/diff 存放位置），并在报告中写明"该补丁不会随包升级自动保留"。**不得让系统长期依赖一个无人维护的 node_modules 补丁。** |
| **回滚** | 回滚 = 用同目录备份文件覆盖回去（或撤销 patch）；必须在执行前写好回滚步骤与其预期输出。 |

### 1.6 reload / restart 条件（重要）

- 优先尝试**正常 reload**（不重启）。
- **如果必须 restart**：
  1. 先确认**没有 running 的 Crew jobs**（无正在执行的任务）；
  2. 由**协调者安排**重启时机；
  3. 重启**不得导致已有聊天丢失**（先确认会话持久化状态，再重启）；
  4. 在报告里写明"重启前 / 重启后"各自的运行状态证据。

## 2. 问题二：Crew preset 声明式注册

### 2.1 现象（已实测）

- `dsh_worker_config` 设 `preset_flash='crew'` 后，实际 spawn 返回：**`Unknown agent preset: crew`**。
- 会话 `hub-6-muyzaglv` 已取消，并恢复为 `standard`。
- **未修改 `flash-only`。**

### 2.2 根因（两边证据）

| 侧 | 证据 |
| --- | --- |
| 旧注册方式 | Crew 插件 `host/crew.js` 把 preset 的 YAML 放在 **`C:\Users\Hi\.dsh\.agent-presets\crew`**（**已实查路径**，不是"两种候选写法之一"） |
| 新 registry | 新版 registry 是**声明式注册**，需要用 `@deepseek-ai/dsh-agent-preset`（同 `node_modules\dsh-agent-preset\lib\index.js`）配置 |
| **根因** | **声明式 registry 未扫描上述旧目录** —— 根因是"扫描范围"问题，**不是目录名写法或目录名猜测问题**（原 v1 把它写成路径待核实，属于错误归因，本版更正） |

### 2.3 提案修复原则

- 用声明式注册配置一个 preset：
  `{ id: 'crew', name: 'Crew', plugins: [ ...当前有效标准 composition 的真正 crew roles ] }`
- **不改当前其它会话的 default**。
- **不影响 `flash-only`**。
- **不关闭 guard**。
- **需要完整验证**：`crew_engineer` / `crew_qa` 等角色可用，**且限制生效**（只读角色仍写不了、PM 保护路径仍被拒）。

### 3.1 备份

### 3.3 修改 preset 注册

### 3.5 回归矩阵（**必须四项全做，任何一项不通过即回滚**）

| # | 用例 | 期望结果 | 说明 |
| --- | --- | --- | --- |
| R1 | 真实子代理写**项目任务领地**内的文件 | **成功** | 修复目标之一 |

| R3 | **PM 的 PTC 嵌套 write** | **被拒绝** | 修复第二个方向（见 1.3） |

### 3.6 兼容性适配规则

- 需要同时支持新旧核心时：以**明确版本判定 / 能力探测**为前提，并且**每一条判定都要有证据**（文件、行号、版本号）。
- **禁止**任何形式的"存在 `parent` 即放行"。
- 兼容层要写成**可删除**的：一旦不再需要旧版本支持，删掉它不应影响正确性。

### 3.7 记录

- 执行报告必须写明：改前/改后判定逻辑、备份路径、durablepatch 路径、reload/restart 情况、R1–R4 的**真实输出**（贴原文，不转述）。

## 4. 明确禁止的做法（写成禁止清单，防止"修法"走偏）

1. **禁止 shell 绕过**：不用 shell 命令、脚本或重定向替代 `write` 去达成同样效果。
2. **禁止禁用守卫**：不临时关闭、不加跳过开关、不设环境变量短路。
3. **禁止伪造身份**：不改 session header、不伪造 `origin: 'subagent'`、不让 root worker 冒充子代理。
4. **禁止"存在 parent 就放行"**：这正是本次缺陷的成因，不得作为兼容手段复活。
5. **禁止改错副本后当作已修**：未确认运行期加载路径前不得改文件。
6. **禁止扩大改动面**：不改其它角色、不动其它会话 default、不动 `flash-only`、不动服务器、不动任何产品代码。
7. **禁止在无人审阅的情况下执行**：本 CRD 的两项都要用户明确接受。

- **先证伪再修**：不为"看起来合理"的判定开绿灯，先确认运行期加载的到底是哪一份安装。

- **补丁要可删**：兼容层不是长期结构，必须能整块删除。
- **不允许削弱守卫换进度**：开发进度永远不能靠关掉守卫来换。
