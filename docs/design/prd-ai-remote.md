## 1. 背景与问题（Problem）

用户的本机（Windows）上跑着 AI 编码会话（Codex、DSH 等）。用户想离开电脑时，用 Android 手机继续看这些会话、继续发消息、看到实时进展、需要时停止任务。**接入的会话来源要求是 Codex 与 DSH 两者都要，不是先后顺序**（见第 2 节 C2）；两类会话的接入能力目前都尚未实现验证。

要做到这一点，必须跨过三道现实障碍：

1. **会话在本机、手机在外网**：本机通常在 NAT 之后，没有公网入口。
2. **会话不是无状态 API**：它是有历史的、正在跑的进程，还带权限与工具调用。手机端不能"重放"会话，只能操作已存在的那个会话。
3. **安全边界很硬**：一旦把本机会话能力暴露到公网，任何转发、日志、下载环节都可能泄露认证凭据、代码与聊天全文。

由此本文档要解决的问题是：

> 让用户在外网、只用一台 Android 手机，就能对**已在电脑上打开的那个 AI 会话**做"看列表、看历史、继续发送、看实时输出、按实际能力停止"这五件事，同时服务器不保存聊天全文，认证 token 不进源码、不进日志、不进公网下载链路，权限不外扩。

### 1.1 使用者与场景（User / Scenarios）

- **使用者**：只有用户本人（自用单用户系统）。
- **场景 A（离开电脑后继续）**：用户在电脑上开好一个会话，出门后用手机打开 App，看到会话列表 → 打开那条会话 → 看到历史 → 继续发一条消息 → 看到新输出逐条出现。
- **场景 B（长任务观察）**：电脑上任务在跑，用户在手机上看输出；需要时点停止（前提：该会话上报的 capability 声明支持停止）。
- **场景 C（配对）**：用户第一次装 App，需要一个短时、一次性的配对动作把手机和设备绑定，不需要在手机上手工敲长期密钥。

## 3. 架构总览（正文，尚未开发）

### 3.1 三个模块

| 模块 | 运行位置 | 技术（**协调者建议，待实现验证**；不是用户已确认项） | 当前状态 |
| --- | --- | --- | --- |
| **desktop**（桌面 bridge） | 用户的 Windows 电脑 | Node 22，**免安装轻量**，依附"原桌面会话"（**协调者建议，待实现验证**） | **尚无有效代码与有效报告**：`desktop/` 下当前只有约 7 字节的 `probe.txt` 占位文件 —— **不是**有效报告，也**不是**代码 |
| **relay**（中转服务器） | 101.43.98.18（CentOS Stream 9, 2C2G） | Go（低内存）+ SQLite；Caddy 反向代理与 TLS；Certbot 自动续期（**协调者建议，待实现验证**） | 目录**已存在**（`desktop/relay/mobile` 已由协调者创建），但 **relay 目录为空**；**尚未开发**，**尚未部署** |
| **mobile**（Android 客户端） | 用户的 Android 手机 | Java + WebView，release 构建的 APK（**协调者建议，待实现验证**） | **尚未开发**：`mobile/.tools/` 下只有工具与下载缓存；其中的 **SDK zip 可能只下载了一部分，使用前必须校验** |

### 3.2 数据流（计划）

```
Android App (Java WebView)
        │  HTTPS（自用，公网 IP 101.43.98.18）
        ▼
Caddy（TLS 终止、反代）
        ▼
relay（Go + SQLite：配对、鉴权、白名单、转发、短时状态；不落聊天全文）
        ▲
        │  出站长连接（电脑主动连服务器，手机无需直连电脑）
        │
desktop bridge（Node 22，运行在 Windows 上，依附原桌面会话）
        ▼
本机已打开的会话（Codex 与 DSH 两者都要支持）
```

关键点，按顺序：

1. **由电脑主动出站连接** relay，服务器与手机都不直连电脑。
2. **relay 只做转发与短时状态**：配对码、会话白名单、在线状态可短暂存在；**聊天全文不落盘**（C9）。
3. **desktop bridge 只读原会话、只通过白名单操作**，不扩权、不改会话历史（C3、C9）。
4. **能力协商**：desktop 上报每个会话的 capability（例如是否支持 `stop`），手机端 UI 按上报能力启用或置灰按钮。**"按实际 capability"是硬要求**：不支持的按钮不得假装可用。

### 3.3 安全设计要点（计划）

- **配对（C8）**：手机请求配对 → 桌面端确认 → 下发**一次性、5 分钟有效**的配对码/凭据 → 手机凭它换取短期凭据使用。过期即失效，用后即废。
- **token 存放与流动（C9）**：不进源码仓库、不进任何日志、不进公网可下载的任何打包物（APK、ZIP、服务器二进制都不含 token）。
- **权限不扩张（C9）**：手机端能做的操作是电脑端权限的子集；**白名单之外**的会话不可见、不可操作。
- **最小留存（C9）**：服务器不保存聊天全文。

> 以上 3.3 的具体机制（例如凭据是短期 JWT 还是随机令牌、配对确认在桌面端还是云端、白名单以什么形式存）属于**待设计确认项**，见第 6 节。本文档只锁定约束，不锁定机制。

## 5. 模块任务领地（Territory）与接缝

### 5.1 任务领地

三个模块在**代码目录上互不重叠**，这是并行开发的前提。建议领地（**待任务表最终确认**）：

| 模块 | 代码领地（建议） | 现状 |
| --- | --- | --- |
| desktop | `desktop/` | 仓库已有该目录（仅 1 个约 7 字节的 `probe.txt` 占位文件） |
| relay | `relay/` | **目录已存在但为空**（需在其中新建文件） |
| mobile | `mobile/` | 仓库已有该目录（目前只有工具与下载缓存；SDK zip 可能下载不完整） |

**硬规则**：一个任务不能同时拥有两个模块的文件；跨模块的改动必须由接缝任务承担（见 5.2）。文档领地 `docs/` 由 PM/架构角色写，不属于产品代码领地。

### 5.2 接缝与 seamowner（Seam owner）

模块之间的边界叫**接缝**。接缝两边必须遵守同一份接口约定；接口约定的编写者叫 **seamowner（接缝负责人）**。

本作业的接缝：

| 接缝 | 两侧 | 载体 | seamowner |
| --- | --- | --- | --- |
| desktop ↔ relay | Node bridge ↔ Go relay | 线上协议（需接口文档） | **Codex 协调者** |
| relay ↔ mobile | Go relay ↔ Java/WebView 客户端 | HTTP/HTTPS 接口（需接口文档） | **Codex 协调者**，**DSH PM 共同把关** |

**总接缝责任**：**Codex 协调者 + DSH PM** 共同承担。含义：

- 接口约定一旦确定就是"冻结"的：任何一侧想改，必须走文档变更流程（本作业为 **CRD**），不允许某一侧私自改协议。
- 两侧可以并行写代码，但都以同一份接口文档为准。
- 接口文档的落点建议在 `docs/design/api/<caller>-<callee>.md`（**尚未创建**，属于设计阶段的产物）。

### 5.3 三模块交付边界

- **desktop**：只负责"把已打开的会话读出来 + 把手机发来的操作按白名单转给会话 + 上报 capability"。
- **relay**：只负责"配对、鉴权、白名单、转发、在线状态；不落聊天全文"。
- **mobile**：只负责"配对、列表、历史、发送、实时轮询、按 capability 停止"；它不实现业务逻辑，也不缓存完整会话历史到服务器。

### 6.5 不做（Out of scope）

**只有"越过后会造成真实代价"的事才写在这里**：代价 = 已完成的工作要重做、不可撤销（已发布/已打标签/数据已删）、或削弱安全守卫。

- **不把认证 token 放进源码、日志或任何公网可下载的产物**（C9）。越过它等于凭据已经泄露，只能作废重发，且可能已经泄露了会话内容。

## 7. 验收标准（Acceptance）

验收分两层：**无命令的判据**（用户能自己判断）与**有命令的验证**（任何人能重复执行）。逐条命令与判据由 `docs/tasks/` 中对应任务行的 **DoD 段落**承担并在那里保持唯一。

### 7.1 A 组：真实同会话发送与桌面同步

1. 电脑上**已经打开**一个 Codex 会话（C3）。
2. 手机上能看到该会话出现在列表中。
3. 手机打开该会话，能看到**已有历史**。
4. 手机发送一条消息后，**电脑上同一个会话**确实收到并继续执行（不是另开一个会话、不是重放）。
5. 电脑上的新输出，在手机上能逐条看到（**实时轮询**）。
6. 该会话上报 capability 支持停止时，手机上点停止能真的停；不支持时按钮不可用且不假装可用。

### 7.2 B 组：真实产物

7. **APK**：`release` 构建，装在真实 Android 手机上可安装、可启动、可完成 A 组全部动作。
8. **Windows ZIP**：免安装，解压即运行，能连 relay 并依附已打开会话。
9. **Linux 二进制**：在 CentOS Stream 9（2C2G）上可直接运行；实测常驻内存符合 2G 机器的低内存要求。

### 7.3 C 组：服务器与外网

10. **serverTLSautoRenew**：证书自动续期任务存在且能在到期前自动续期（不是只签一次）。
11. **外网可访问**：手机在非局域网网络下可访问 101.43.98.18 的 HTTPS 服务。
12. **API auth**：无凭据或用过期凭据的请求被拒绝；错误凭据不允许访问任何会话数据。
13. **pair 确认**：一次性 5 分钟配对生效 —— 超时后配对码失效；配对成功后同一配对码不可再次使用。

### 7.4 D 组：安全约束（C9）

14. **token 不在源码**：仓库全量检索不到任何真实 token/密钥（只允许占位符与文档说明）。
15. **token 不在日志**：relay 与 desktop 的日志中不出现 token 或等效凭据。
16. **token 不在公网下载**：APK、Windows ZIP、服务器二进制解包后都不含 token。
17. **不保存聊天全文**：服务器磁盘/数据库中不存在会话消息全文（SQLite 里只有配对、白名单、状态类短时数据）。
18. **仅白名单会话**：白名单之外不存在的会话 ID，无法被列举、打开或操作。

### 7.5 E 组：本作业自身的前置条件

19. 真实子代理能写自己的任务领地（修复后），且**根 PM 直写保护路径仍被拒绝**、**只读 reviewer 写入仍被禁止**、**PM 的 PTC 嵌套写仍被拒绝** —— 详见 `docs/tasks/T-0001-dsh-compatibility.md`。
20. Crew 角色（`crew_engineer` / `crew_qa` 等）在独立会话中可被正常 spawn，且写入限制照旧生效。
